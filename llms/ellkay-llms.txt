# LKCloud API Documentation

> Documentation for LKCloud API

## Guides
- [Authentication](https://lkcloud-api.readme.io/docs/authentication-2.md): LKCloud APIs use the OAuth 2.0 protocol for authentication and authorization.

## API Reference
- [GetAppointments](https://lkcloud-api.readme.io/reference/post_lkappointments-getappointments.md): The GetAppointments endpoint returns a list of appointments, each containing details such as ID, start time, duration, and associated patient and physician IDs.              Does not include deleted or cancelled appointments

- [SmartSearch](https://lkcloud-api.readme.io/reference/post_lkbridge-smartsearch.md): Search using a pipe-delimited string. Supported parameters include last name, first name, social security number, chart number, date of birth, phone number, gender, facility ID, home phone, mobile phone, ZIP code, external ID and MRN. All search parameters are combined with an AND logic and use partial matching. For example, a chart number ""ABCD"" might match ""ABC"" and ""ABCD.""              Each search field is interpreted based on its position in the pipe-delimited string. If you want to search by chart number only, your search string would look like ""|||my-chart-number||"". Omitting trailing pipes, such as ""|||my-chart-number"", is also valid.              Here are the supported search fields:              Last name: Free text (e.g., Smith) First name: Free text (e.g., Jane) Social Security Number: nnn-nn-nnnn (e.g., 123-45-6789) Chart Number: Free text(e.g., 00AAB) Date of Birth: MM/dd/yyyy(e.g., 08/31/1984) Phone Number: +n-nnn-nnn-nnnn(e.g., +1-201-123-4567) Gender: Supports “M”, “F”, and “U” Facility ID: Free text(e.g., 123) Home Phone: +n-nnn-nnn-nnnn(e.g., +1-201-123-4567) Mobile Phone: +n-nnn-nnn-nnnn(e.g., +1-201-123-4567) ZIP Code: Free text(e.g., 08394) External ID: Free text(e.g., 12345) MRN: Free text(e.g., 00046057)  Example query: ""last-name|first-name|social-security-number|chart-number|date-of-birth|phone-number|gender|facility-id|home-phone|mobile-phone|zip|external-id|mrn""

- [ApplyPayment](https://lkcloud-api.readme.io/reference/post_lkpatientbalance-applypayment.md): Record a payment that has been made for the given patient. Supports copay's, specific encounter payments, and payments to the overall patient account. ## Payment Batches It's recommended that you provide a batch name and date with each payment message, which tells our adapter which payment batch to attach the payment to.  If no payment batch data is provided with the message, the adapter will attach the payment to today's open batch. If more than one open batch is found, the payment will fail.  The adapter automatically creates a new batch when zero batches exist, but it won't create a new batch when there are 1 or more batches. More than one matching batch causes a failure. ## Post "Kind" Each payment message must include a "PostKind" enum. The options are Copay, Deposit, or Balance. ### Copay Copay payments required a visit ID be sent with the message, so we can record the copay for the correct visit. ### Deposit Deposit payments are simply recorded on the patient record. They are not posted to a particular visit or service. ### Balance Balance payments are recorded on the patient record, but also applied to services rendered for the patient. When a visit id is included with the message, the payment is only applied to a specific visit. If a visit id is not included with the message, the payment will be applied using the target systems first-in, first-out (FIFO) payment logic. Typically, this means the payment total amount is applied to the oldest visit with outstanding charges first, then to the second oldest visit, etc. Once the FIFO operation is completed, any remaining amount is deposited to the patient account.
